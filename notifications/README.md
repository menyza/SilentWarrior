# תזכורות Cloudflare Workers + D1

השירות מוכן בקוד, אך אינו פרוס ואינו שולח תזכורות עד השלמת החיבור ובדיקה באייפון. שתי תזכורות כלליות בשעה מקומית לפי IANA, Cron כל 5 דקות. משקל והיסטוריית הרגלים אינם נשלחים לשרת. אין ביטול אוטומטי לפי השלמות בגרסה זו.

## בדיקות

```sh
cd /workspace/SilentWarrior/notifications
npm ci
npm test
WRANGLER_SEND_METRICS=false npm run test:runtime
```

Node 24 נדרש. בדיקת runtime מפעילה את Cloudflare workerd ו־D1 מקומית, עם הצפנה וחתימת VAPID אמיתיות, אך ספק ה־Push מוחלף בתחליף לבדיקה. הצלחתה אינה מסירה אמיתית למכשיר.

## הכנת החשבון

נדרשים CLOUDFLARE_ACCOUNT_ID וחיבור מורשה דרך CLOUDFLARE_API_TOKEN בהגדרות הסביבה המאובטחות, או wrangler login במחשב אישי. אין לשלוח מפתחות בצ׳אט. צור API Token מותאם, מוגבל לחשבון שלך: Account / Workers Scripts / Edit; Account / D1 / Edit; Account / Account Settings / Read. Workers subdomain פעיל נדרש. אם האתר מבקש אימות או בחירת תוכנית, יש להשלים באתר; אין הבטחה למסלול או למכסות לפני בדיקה בחשבון. Account ID מופיע בפרטי החשבון.

## פריסה

```sh
cd /workspace/SilentWarrior/notifications
npx wrangler d1 create silent-warrior-reminders
```

המסד silent-warrior-reminders כבר נוצר דרך האתר, ומזההו הוגדר ב־wrangler.jsonc. שם ה־Worker הוא silentwarrior כדי להתאים לפרויקט Workers Builds. אין ליצור מסד נוסף. לבדוק ש־APP_ORIGIN הוא מקור האתר המדויק ללא נתיב, וש־VAPID_SUBJECT הוא URL או mailto תקין. לאחר מכן:

```sh
npm run keys
npx wrangler d1 migrations apply silent-warrior-reminders --remote
npm run deploy
npx wrangler secret bulk .dev.vars
```

פקודת keys יוצרת בקובץ המקומי המוגן והמתעלם מ־Git, .dev.vars, מפתחות VAPID וקוד חיבור. היא אינה דורסת קובץ קיים. לשמור את הסודות באחסון מאובטח, לא להדפיס, לשתף בצ׳אט או להעלות ל־Git. secret bulk מעלה את ערכי הקובץ ל־Worker; עד השלמתו API מחזיר 503. מפתח VAPID הפרטי נשאר בשרת. שינוי מפתחות עלול לחייב רישום מכשירים מחדש. את קוד החיבור מזינים רק בממשק האפליקציה שלך; הוא אינו נשמר לאחר הרשמה.

## בדיקה באייפון

1. iOS 16.4 ומעלה: לפתוח ב־Safari, שיתוף ← הוסף למסך הבית, ולפתוח מהאייקון.
2. ב״ההרגלים שלי״ להזין את כתובת workers.dev, קוד חיבור, שעות ואזור זמן.
3. ללחוץ חיבור ולאשר התראות. לשרת נשלחים רק endpoint ומפתחות הרשמת Push, שעות ואזור זמן. token ניהול ייחודי נשמר בדפדפן; ה־hash שלו ב־D1.
4. לשלוח בדיקה ולוודא שהתראה מופיעה כשהאפליקציה סגורה ופותחת אותה.
5. לבדוק תזכורת מתוזמנת וכיבוי לפני הכרזה על מוכנות.

השירות שולח פעם אחת לסוג ותאריך מקומי, בחלון 10 דקות ממועד התזכורת. משלוח שנכשל ניתן לניסיון חוזר בחלון הבא. אין backfill אחרי הפסקה ארוכה, וזמן המסירה אינו מובטח. מגבלה: 20 מכשירים. קוד חיבור מגביל הרשמה; endpoints מוגבלים לספקי Apple/Google/Mozilla. בדיקה מוגבלת לפעם בדקה. כיבוי מוחק מ־D1 ומבטל הרשמה במכשיר. מחיקת נתוני הדפדפן לבדה אינה מוחקת הרשמה בשרת; אפשר להירשם שוב עם אותו קוד ואז לכבות. השירות מיועד לשימוש אישי, לא לשירות ציבורי רחב. קוד חיבור שנחשף צריך החלפה.

## חסמים שנותרו

החשבון טרם חובר לסביבת העבודה, אין מזהה D1 אמיתי או סודות Worker פרוסים, ולא בוצעה מסירה לאייפון. API הפריסה דורש api.cloudflare.com. בדיקת שרת פרוס דורשת גם גישה לכתובת workers.dev המדויקת. הגדרות הצפנה ותזמון מקומיות אינן מחליפות פריסה ובדיקת מכשיר.

בפריסה דרך GitHub: Root directory /notifications; Build command npm ci; Deploy command npx wrangler deploy. יש להחיל את migrations/0001_subscriptions.sql דרך D1 Console או באמצעות פקודת migrations לפני שימוש. פריסה רגילה אינה מחילה migrations אוטומטית.

חלופה להגדרת המפתחות דרך לוח Cloudflare: לפתוח את setup-notifications.html באתר GitHub Pages וליצור מפתחות בדפדפן. היצירה משתמשת ב־Web Crypto P-256 ובאקראיות קריפטוגרפית; אין בקשות רשת או שמירה מקומית של המפתחות. להעתיק את שלושת הערכים ל־Worker Settings / Variables and Secrets כסוג Secret, ולשמור עותק במנהל סיסמאות. אין ליצור זוג חדש לאחר הרשמת מכשירים אלא כחלק מסיבוב מפתחות מתוכנן. דף זה אינו חלק ממסכי האפליקציה או ממטמון ה־Service Worker.

ה־Worker כולל כעת גם API חשבונות וסנכרון באותו DB. טבלאות נוספות נוצרות באופן לא הרסני בבקשת חשבון ראשונה; השירות הקיים לתזכורות נשאר באותו נתיב ובאותן הרשאות. ראו ../ACCOUNT-SETUP.md להפעלה ולבדיקות.

## הרשמה עצמאית לחשבון מחובר

לאחר כניסה לחשבון, במסך ההרגלים אפשר להפעיל התראות ללא `ENROLLMENT_KEY`. נדרשים רק DB ומפתחות VAPID הקיימים. כל מכשיר מקושר לחשבון המאומת, עם אזור זמן, שעות בוקר/ערב וכיבוי נפרדים. אפשר לשלוח בדיקה או לכבות את המכשיר הנוכחי; הכיבוי אינו משנה מכשירים אחרים. המכסה היא 20 מכשירים לחשבון. יציאה מהחשבון אינה מכבה תזכורות: יש לכבות לפני יציאה אם רוצים להפסיק אותן. במכשיר משותף יש להתחבר לבעל ההרשמה ולכבות אותה לפני הפעלה בחשבון אחר.

הנתיבים `POST /push/subscription` ו־`GET/PUT/DELETE /push/subscription/:id`, וכן `POST /push/subscription/:id/test`, דורשים Bearer של session חשבון תקף. השרת קובע את הבעלים מה־session בלבד. ידיעת מזהה מכשיר או endpoint אינה מאפשרת גישה להרשמת משתמש אחר.

ההרשמות הישנות והניהול באמצעות אסימון מכשיר ממשיכים לעבוד. עדכון שעות בהרשמה ישנה בזמן שהמשתמש מחובר משייך אותה לחשבון, באמצעות אסימון המכשיר כהוכחת בעלות. השיוך אינו מאפס את סימוני המשלוח היומיים; אסימון המכשיר הישן מתבטל, והניהול ממשיך דרך החשבון. קוד ההרשמה הישן אינו יכול לדרוס מכשיר שכבר משויך לחשבון.

יש לפרוס את ה־Worker ואת קובצי האתר המעודכנים יחד. טבלת הבעלות והאינדקס נוצרים באופן לא הרסני בבקשת התראות ראשונה; `migrations/0004_subscription_owners.sql` מתעד את אותו שינוי וניתן להחיל אותו גם דרך מסלול migrations הקיים. אין להחליף DB, לסובב מפתחות VAPID או למחוק הרשמות. אין צורך ב־ENROLLMENT_KEY עבור התראות של חשבון מחובר; הוא עדיין נדרש להרשמת אורח ישנה ולהזמנת חשבון Passkey לפי המדיניות הקיימת.

בדיקות: `npm test` ו־`WRANGLER_SEND_METRICS=false npm run test:runtime` בתיקיית notifications. בדיקות דפדפן מהשורש: `python3 tests/browser_reminders.py` למסלול הישן ו־`python3 tests/browser_account_reminders.py` למסלול החשבון. בדיקות Push משתמשות בספק מדומה; מסירה אמיתית דורשת בדיקה במכשיר.

## התראות אישיות

בהגדרות ← התראות ושעות אפשר להוסיף ולמחוק עד 20 תזכורות יומיות, עם סוג ושעה לכל תזכורת, בחזרה יומית. שמירת התראות מעדכנת את המכשיר הנוכחי של המשתמש המחובר; הרשאת Push והרשמה נדרשות בכל מכשיר. רשימת הנושאים והשעות כלולה גם בסנכרון ובגיבוי החשבון. לאחר שחזור הגדרות לחשבון יש לשמור אותן במסך ההתראות כדי לעדכן את שירות השליחה למכשיר.

יש לפרוס את האתר ואת ה־Worker המעודכנים יחד: השרת הישן תומך רק בבוקר וערב ואינו מקבל רשימה אישית. הרשמות בוקר/ערב קיימות ממשיכות לעבוד. אין צורך להחליף DB או לסובב מפתחות VAPID. טבלת `reminder_deliveries` נוצרת באופן לא הרסני בהרצת המתזמן הראשונה; `0005_reminder_deliveries.sql` מתעד את המבנה. כל תזכורת נשלחת בנפרד, לכל היותר פעם לתאריך מקומי; שליחה שנכשלה משתחררת לניסיון חוזר בחלון התזכורת. ה־Service Worker משתמש בתג נפרד לכל תזכורת כדי שתזכורות שונות לא יחליפו זו את זו.

לפני פריסה נדרשים גישה אל `api.cloudflare.com`, הרשאת Cloudflare מתאימה ו־Account ID בהגדרות הסביבה המאובטחות. בדיקת השירות דורשת גישה ל־`silentwarrior.menyzakar142.workers.dev`. בדיקות מקומיות משתמשות בספק Push מדומה ואינן מוכיחות מסירה למכשיר אמיתי.

תדירות אישית: לכל תזכורת בוחרים סוג ושעה; כל ההתראות חוזרות מדי יום. אזור הזמן נשמר בהעדפות המשתמש. הגבלות ימים ישנות מתעלמות כדי שההפעלה תהיה יומית. תזכורת סמוכה לחצות נבדקת גם בהרצת המתזמן הראשונה ביום הבא ומשויכת לתאריך המקורי.


## מדידת כניסות וזמן שימוש

`POST /account/usage` מקבל עד 20 רשומות כניסה עם מזהה, התחלה, פעילות אחרונה ומילישניות פעילות. נדרש session תקף, והשרת קובע את המשתמש מהאימות. כתיבה חוזרת משתמשת במקסימום המצטבר ואינה מגדילה את מספר הכניסות. `GET /account/usage` מחזיר סיכום לחשבון המאומת בלבד. טבלת `usage_sessions` והאינדקס נוצרים בנתיב schema הקיים באופן לא הרסני; migrations/0006_usage.sql מתעד את המבנה. scripts/usage-report.sql הוא דוח מנהל לקריאה בלבד, עם תאריכים ב־UTC.

שדות השתייה `water` ו־`waterGoal` נשמרים במסמך החשבון. לקוחות ישנים שמשמיטים אותם לא מוחקים את הערכים הקיימים. רשומות שתייה נבדקות בשרת ומזוהות במזהים יציבים כדי לאפשר מיזוג בין מכשירים.
